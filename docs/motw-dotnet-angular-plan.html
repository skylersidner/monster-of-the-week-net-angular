🎨 Tailwind CSS + Angular — Compatibility Assessment

✅ No issues — Tailwind 4 works natively with Angular 21. The old postcss7-compat workaround needed for CRA is completely unnecessary here. Angular 21's @angular/build uses Vite/esbuild under the hood, and Tailwind 4 ships a first-class Vite plugin. Setup takes < 5 minutes.

Why Tailwind Worked Poorly Before

The current UI uses @tailwindcss/postcss7-compat because Create React App 4 bundles PostCSS 7, which is incompatible with Tailwind 3+. CRACO was added solely to inject a PostCSS 8 pipeline without ejecting CRA.

None of this applies to Angular. The Angular CLI has never had this limitation.

Tailwind 4 Setup in Angular 21

# Install Tailwind 4 and its Vite plugin
npm install tailwindcss @tailwindcss/vite

# In vite.config (via angular.json plugin config)
# or use the Angular CLI integration:
ng add tailwindcss

In src/styles.css (or styles.scss):

/* Tailwind 4 — single import replaces the 3-directive pattern */
@import "tailwindcss";

Tailwind 4 auto-detects content files. No tailwind.config.js required (though supported for customization).

Migrating Existing Tailwind Classes

The existing UI's Tailwind classes (indigo nav, responsive layout) will mostly work unchanged in Tailwind 4. The main things to update:

  • Replace the 3-directive import with @import "tailwindcss"
  • Verify any custom colors still resolve (indigo palette is unchanged)
  • Update darkMode if used (class strategy syntax changed slightly)
  • Any @apply directives still work
  • The bg-indigo-600, max-w-7xl, text-lg etc. classes from the existing layout are identical in Tailwind 4
💡 Tailwind provides an official upgrade tool: npx @tailwindcss/upgrade to handle most class renames automatically.

API Layer Responsibilities

Controllers

  • Route binding and HTTP verb mapping
  • Input validation (model state)
  • HTTP status code selection
  • No business logic — delegate to Services

Services

  • Business logic and validation rules
  • Entity ↔ Contract mapping
  • Orchestrate multiple repository calls

Repositories

  • All EF Core / database queries
  • Eager loading of navigation properties
  • No mapping — return entities

Angular Layer Responsibilities

Feature Services (e.g. MysteryService)

  • Wrap HttpClient calls with typed responses
  • Return Observable<T> to components
  • Handle error mapping

Components (standalone)

  • Inject services via inject()
  • Use AsyncPipe for subscription management
  • Tailwind classes for styling directly in template

Core Module (singleton)

  • HTTP interceptors (auth, error handling, loading)
  • App-wide models/interfaces
  • Signal-based state (Angular Signals, no NgRx needed for this app size)

📋 REST API Contract Design

GraphQL's flexible querying is replaced by a conventional REST hierarchy. The root resource is Mystery — all other entities are scoped through it or through their direct parent. Lookup tables (types) are read-only reference endpoints seeded at startup.

💡 Design philosophy: Mystery detail responses embed nested counts/summaries to avoid N+1 client round-trips. Full sub-resource lists are fetched separately only when a user navigates to that section. This mirrors how the existing UI was structured (mystery detail page → monster detail panel).

🗄️ Entity Framework Core Data Model

The existing PostgreSQL schema (18 tables) is preserved almost exactly. EF Core code-first migrations will replace Knex migrations. The only meaningful adaptations are timestamp types and the addition of UpdatedAt auto-update handling.

Schema Adaptations from Current Design

ChangeReason
timestamps(true,true) → created_at + updated_at as DateTimeOffset Knex's timestamp helper maps directly. EF Core uses DateTimeOffset for timezone-aware storage (Npgsql maps to timestamptz).
Add SaveChangesAsync interceptor to auto-update updated_at Knex's timestamps(true, true) auto-updated on write; EF Core needs a DbContext.SaveChanges override or a SavingChangesEvent handler to replicate this.
Rename join table to monster_attack_weapon_tags (singular "attack") Minor naming consistency; existing data migrates cleanly.
All uuid PKs → Guid in C# Direct mapping; uuid_generate_v4() replaced by Guid.NewGuid() in entity constructors.
No schema changes to column names or foreign keys EF Core's ToTable() + HasColumnName() map C# PascalCase properties to existing snake_case columns.

    public override async Task<int> SaveChangesAsync(...)
    {
        // Auto-stamp UpdatedAt on modified entities
        foreach (var entry in ChangeTracker.Entries<ITimestamped>()
            .Where(e => e.State == EntityState.Modified))
            entry.Entity.UpdatedAt = DateTimeOffset.UtcNow;

        return await base.SaveChangesAsync(...);
    }
}

// In OnModelCreating:
modelBuilder.Entity<Mystery>(entity => {
    entity.ToTable("mysteries");
    entity.HasKey(m => m.Id);
    entity.Property(m => m.Id).HasColumnName("id");
    entity.Property(m => m.Name).HasColumnName("name").HasMaxLength(255).IsRequired();
    entity.Property(m => m.CreatedAt).HasColumnName("created_at");

    entity.HasOne(m => m.Countdown).WithOne(c => c.Mystery)
        .HasForeignKey<Countdown>(c => c.MysteryId);
});

⚛️ Angular 21 Application Structure

Angular Feature Architecture

Uses standalone components (Angular 17+ default) with lazy-loaded routes. No NgModules required. Signals replace simple RxJS state where appropriate.

Core Services (singleton, provided in root)

  • ApiService — base URL config, shared error handling
  • MysteryService — mystery CRUD + countdown
  • MonsterService — monster + all sub-resources
  • LocationService — location CRUD + custom moves
  • BystanderService — bystander CRUD + custom moves
  • ReferenceDataService — lookup types + weapon tags (cached)

HTTP Pattern

// mystery.service.ts
@Injectable({ providedIn: 'root' })
export class MysteryService {
  private http = inject(HttpClient);
  private base = '/api/mysteries';

  getAll(): Observable<MysteryListItem[]> {
    return this.http.get<MysteryListItem[]>(this.base);
  }

  getById(id: string): Observable<MysteryDetail> {
    return this.http.get<MysteryDetail>(`${this.base}/${id}`);
  }

  create(req: CreateMysteryRequest): Observable<MysteryDetail> {
    return this.http.post<MysteryDetail>(this.base, req);
  }
}

DecisionChoiceRationale
API style REST (no GraphQL) Simpler contracts, conventional HTTP tooling, matches portfolio pattern
Angular standalone vs NgModules Standalone components (Angular 21 default) Less boilerplate, tree-shakeable, lazy loading built-in
State management RxJS services + Angular Signals (no NgRx) App complexity doesn't warrant a full state library; signals handle local/shared state
EF Core vs Dapper EF Core 10 (same as portfolio) Code-first migrations; strongly typed queries; schema matches 1:1 with entities
Authentication Not in scope (not in original app) Can be added later; JWT + ASP.NET Core Identity is the natural fit when needed
Swagger / OpenAPI Add Swashbuckle for dev-time exploration Replaces Apollo Studio; useful while building Angular services against the API
Mystery detail response Embedded countdown + entity counts; sub-resources fetched on demand Avoids N+1 client calls for the list view; matches typical UI interaction pattern
