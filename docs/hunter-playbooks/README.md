## Phase summary

**Renumbered 2026-08-29** — a new Phase 6 (custom-move modeling) was inserted between bespoke rulesets and playbook imports, per Skyler's explicit request; old Phases 6–9 are now 7–10.

1. **Data Admin restructuring** — tabs: "Types" (current content, unchanged) + "Playbooks" (placeholder this phase). *Fully specified.*
2. **Standard-vs-bespoke data model for Playbooks** — the core deliverable of this pass. *Fully specified.*
3. **Data Admin UI: Playbook create/update** — shared component, single upsert-the-graph endpoint (no sub-resource endpoints). Purpose: Skyler's own path for future one-off templates, and a manual-testing surface for the create/update functionality — **not** how the canonical 28 get authored. *Fully specified.*
4. **Validate the Phase 2 data model, and pin down a repeatable authoring pattern** — an AI agent authors Chosen/Crooked/Divine's standard-section data via the real API (one bounded task per playbook), against a working/dev database, self-verifying against a known-artifact checklist. No production seed is produced this phase. The procedure gets packaged as a Claude Code Skill during this phase, reused for Phase 8. Formatting fidelity for Moves content uses the approved `pdf-extraction-pipeline.md`/`tools/pdf-extract/` mechanism — resolved, not a spike. *Fully specified.*
5. **Bespoke, playbook-unique ruleset abstraction** — *Validated against all 28 real playbooks, walkthrough complete 2026-08-29.* See `phase5-bespoke-ideation.md` for the design reasoning (including the extensions the walkthrough required), and `bespoke-ruleset-catalogue.md` for the complete, catalogued result.
6. **Custom Move modeling: internal pick-structure within individual Moves** — *Inserted 2026-08-29; design pass done 2026-08-30, open questions pending Skyler.* All 28 playbooks' Moves read in full: 14 creation-time in-move picks across 11 playbooks (half of them newly found, including two on The Crooked — a Phase 4 pilot), ~35 in-play menus, 10 free-text cases, 5 computed-option-set cases. Proposed model reuses `architecture.md` Section 6 wholesale via one nullable FK. See **`custom-moves-ideation.md`** and `phases.md` Phase 6.
7. **Import bespoke data for the three playbooks** — *Deferred*, depends on Phase 5 and Phase 6. Same agent-driven authoring mechanism as Phase 4 once both land.
8. **Import remaining 25 playbooks, then run the one-time production seed conversion** — *Deferred*, explicitly later work per Skyler's brief. Its closing step is now settled: once all 28 are fully authored (standard + bespoke + Move-internal), a one-off script (not ongoing tooling) converts the working data into the production seed, seeded into every environment via an extended `MotwDbInitializer`. After that, further canonical-playbook changes go through normal EF Core migrations, not by re-running the script.
9. **Hunter instance list UI** — sidebar entry, dead-link list page. *Fully specified.*
10. **Hunter create/edit UI** — recommendation: single-page reactive form (like Monster/Minion), not a wizard. *Fully specified, with rationale.*
