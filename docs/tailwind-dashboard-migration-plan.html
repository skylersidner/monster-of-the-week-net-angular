Tailwind Layout Integration Plan (Angular)

Source reference: Svelte layout at C:\Users\malev\projects\monster-of-the-week-svelte\src\routes\__layout.svelte

Goal

Bring the Angular app to a similar Tailwind-style application shell (desktop sidebar, mobile off-canvas menu, top header, routed content area), add a new dashboard landing experience, and keep scope lean for a first pass.

Confirmed Scope Decisions

  • Default landing route should become /dashboard (instead of /mysteries).
  • Sidebar placeholder entries are required, but deferred from first pass (TODO).
  • Header search is visual-only for now (Future Feature).
  • HTTP failures should surface as global toasts for consistency.
  • Dashboard data should be driven by /api/mysteries first (lean scope).
  • Use inline SVG/Heroicons now; Font Awesome can be revisited later (Future Feature).

Component and Route Breakdown

  1. Layout Shell (Page Layout)
    • Desktop narrow sidebar navigation
    • Mobile off-canvas menu + backdrop + toggle state
    • Top header with visual search bar, user menu shell, and quick action button
    • Global toast stack rendered in layout for all routes
  2. Routes
    • Add /dashboard route under existing layout children.
    • Change default child redirect from /mysteries to /dashboard.
    • Keep existing mysteries/detail routes untouched in first pass.
  3. Dashboard Page
    • Summary cards and/or recent list using current /api/mysteries payloads.
    • Simple loading/error/empty states aligned to new layout styling.

Implementation Steps (First Pass)

  1. Refactor Angular page layout template to match Svelte shell structure using Tailwind classes.
  2. Add nav model in Angular layout for shared desktop/mobile rendering.
  3. Implement mobile menu open/close behavior and user menu toggle in layout component state.
  4. Add new Dashboard page component and route.
  5. Update root redirect to /dashboard.
  6. Restyle toast stack to fit shell and preserve dismiss behavior.
  7. Wire global HTTP error handling to notification toasts via interceptor.
  8. Update unit tests for layout behavior and routing redirect change.

TODO List (Must Do Before Full Functional Milestone)

  • Sidebar placeholders: add placeholder nav entries for Monsters, Minions, Locations, and Bystanders in the shell nav model without enabling full route content yet.
  • Dashboard data implementation detail: define and implement the best first-pass dashboard view using only /api/mysteries (counts/summary/recency strategy).
  • Toast consistency audit: ensure mutation successes and failures across key pages surface consistent global toast messaging patterns.

Future Feature List

  • Convert header search from visual-only to real search/navigation behavior.
  • Evaluate Font Awesome-based icon strategy vs inline SVG/Heroicons for long-term consistency.
  • Add richer dashboard data via dedicated aggregate endpoint once scope allows.
