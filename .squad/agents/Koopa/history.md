# Koopa — Retrospective Analyst

## Learnings

### 2026-09-21 — Mystery entity linking retrospective (Phase 6 of its own plan)

- **Deliverable: `docs/updates/mystery-entity-linking-retrospective.md`.** No retrospective convention existed in this repo — nothing matching `*retro*` anywhere. Chose `docs/updates/` as a **fourth companion** to the feature's three authored docs, following Peach's stated rule (*one file per document-with-a-named-author, not sections bolted onto someone else's*). Header shape copied from the acceptance docs: `**Prepared by:**` / `**Status:**` / `**Date:** · branch`, then a blockquote naming the sibling docs and the ownership split. Treat that as the convention for the next one.
- **The primary sources here are unusually good and should be read in this order:** `git log --format="%B"` over the feature range (the commit bodies carry the *reasoning*, not the changelog — `68ea8c5` and `f8170eb` are near-complete post-mortems on their own), then `.squad/agents/*/history.md` (per-phase, with measured counts), then the design docs last. The docs are coordination artifacts; the histories and commits are where the defects and costs live.
- **Yoshi's history keeps a revision-numbered entry per design revision** (rev 1 → rev 12 here, all under `### Mystery ↔ Entity Linking — …, Rev N`). That file alone reconstructs the whole design arc including every reversal. It is the single highest-yield file for a retro on any feature he designed.
- **Toad, Luigi and Bowser all report measured counts per phase** — test totals before/after, negative controls run, how many MISSED, which mutant killed which test. That makes quantitative claims checkable. **Do not accept a "this was expensive" claim without one of those numbers behind it**; this feature had them for almost everything.
- **Method that worked: count findings by the artifact that produced them.** ~50 from code/mutants vs 4 from reading docs against each other. That one tally settled the retro's central claim and took ten minutes. Reach for it whenever a feature has both heavy documentation and heavy review.
- **Check the "it got smaller / it went well" narrative against the decision table.** Yoshi wrote at rev 5 that every stakeholder round made the design smaller; the §3/§3.1/§3.2/§3.3 decision tables show scope grew in three of four rounds (decision 2 monster roster, 7/10 modal, 8/9 upsert+dirty-tracking, 17/18/19). What actually shrank was the *mechanism he'd pre-designed* against an unanswered question. A retro's job is exactly this kind of check.
- **Recurring-observation timing is a measurable thing.** Principle 5 (baseline/draft lifecycle) had 5 instances; it was named at instance 3 and stated too narrowly (existence, not lifecycle), which let instances 4 and 5 through as production bugs found post-implementation. **Tabulate instance → finder → when** for any class that recurs; the gap between "second instance" and "named" is the cost.
- **Friction items cluster.** `--artifacts-path`, the `Copy-Item` mtime trap, `tsc -p tsconfig.json` checking nothing, the stale `dotnet run` lock — individually trivia, together *five build/verification steps that fail silently*, which is the same failure mode as the vacuous tests the feature spent most of its review budget hunting. Group friction by failure mode, not by tool.
- **Repo process facts worth knowing before any future ceremony:** `.squad/decisions.md` has **4 entries (newest content 2026-07-21)** while `.squad/decisions/records/` has **125 files** — the inbox is the real record and nothing drains it, so an agent told to "check standing decisions" gets a two-month-old picture. `.squad/log/` and `.squad/orchestration-log/` are stale since 2026-07-26. `.squad/agents/Mario/history.md` is **empty** — the Lead is on the retrospective roster and has no recorded contribution to any recent feature, while Yoshi and Boo do the most consequential work and are on no roster.
- **Ceremony roster in `.squad/ceremonies.md` is stale** (retrospective: Mario, Luigi, Bowser, Rosalina, Toad, Peach). Read every contributor's history regardless of the roster, and say in the output that you did.

### 2026-09-21 (same day) — Retired `decisions.md`, renamed `inbox/` → `records/`, built the standing index

- **Structure landed:** `.squad/decisions/records/` (archive, 129 files) + `.squad/decisions/README.md` (index of what still binds, 20 entries). `.squad/decisions.md` deleted. **The index lives *inside* `.squad/decisions/`, deliberately** — the old failure was an index sitting outside the thing it indexed, so it could rot without anyone noticing the drift. One path to remember now.
- **The finding that reframed the whole task: the drain had already run once, and it destroyed what it touched.** `986e52d` (2026-07-25) compressed **three** records — `Luigi-mystery-create-frontend-decomposition.md` (261 lines), `luigi-mystery-create-wizard.md` (74) and `luigi-armor-support.md` (70) — into the 29 lines of `decisions.md` and deleted all three. It also **dropped a decision entirely** — "the minion step is optional" survived nowhere and stayed invisible for two months. All three recovered with `git show 986e52d^:<path>`. **Whenever a repo has a merge-and-clear step, check git for what it already ate before designing around it.**
- **Recovering deleted records repaired live citations.** Three pointers had been dead since July (`.squad/orchestration-log/2026-07-21-202001-Luigi.md` ×2, `.squad/skills/angular-wizard-decomposition/SKILL.md` ×1). Nobody had noticed, because a dead markdown link fails silently — same class as the vacuous tests.
- **I reported the loss as two records / 335 lines; it was three / 405, and how I got it wrong is the lesson.** I enumerated the deletion set with a `--diff-filter=D` log against a ***mystery-create*** filename glob — **a pattern encoding what I expected to find.** `luigi-armor-support.md` is *about* the mystery-create wizard but not *named* for it, so it was invisible. `git show --diff-filter=D <sha>` — the commit's own deletion set — is one command and is the truth. **Ask the artifact that defines the set, never a pattern that resembles it.** This is my own promoted index rule (*derive the count, never write it down*) broken while writing the index, and it is the incident's own shape: a summary standing in for the thing it summarised. Caught in review, not by me.
- **The record nothing cites is the dangerous one.** Two of the three left dead links — a symptom anyone could trip over. The armor record was cited by nothing, so its destruction produced **no symptom at all** and was undiscoverable except by reading the commit. Dead-link checking finds only the cited casualties; it is a floor, not a measure.
- **Reference-fixing is much bigger than "the agent definition and CLAUDE.md".** Actual scope: **188 path citations across 45 files** plus **21 content citations across 11**. There is **no `CLAUDE.md` in this repo at all**, the agent definition is at **`.github/agents/squad.agent.md`** (not under `.squad/`), and `.squad/ceremonies.md` had **zero** references. Search, never assume.
- **Two reference classes need different treatment.** A *path* citation (`see .squad/decisions/inbox/foo.md`) is mechanical — rewrite it, meaning is untouched. A *content* citation ("`decisions.md` 2026-07-21 says X") must repoint at wherever that text now lives, which is why the retired file had to be preserved verbatim as a record before deletion.
- **Do not rewrite dated analyses whose subject is the old name.** Excluded `docs/engineering-practice-improvements-plan.md`, `docs/updates/mystery-entity-linking-retrospective.md` and the agent histories from the automated pass, and appended dated completion notes instead. Rewriting "the inbox holds 126 files" into "records" falsifies an observation; marking it superseded does not.
- **`sed` is unsafe for this repo — it strips CR in text mode on mixed CRLF/LF trees** (Luigi's 2026-09-19 finding). Used node with explicit `Buffer` read/write plus a **CRLF-count assertion before writing**, which is what makes a 188-site rewrite safe to do blind.
- **Anchor-based replacement with a uniqueness check is the right shape for governance-file edits.** 15 edits to `squad.agent.md`, each failing loudly if its anchor were missing or appeared twice. Then verified by link-checking all 186 record citations: 185 resolve, 1 known-unresolvable (`luigi-theming-phase1-utility-name-stutter.md`, cited as superseded but never committed to git).
- **The most important edit was deleting a step, not repointing a path.** Scribe's charter said *"Merge `decisions/inbox/` → `decisions.md`, delete inbox files"*. Retiring `decisions.md` while leaving that instruction in place would have had the next Scribe recreate the file and delete records again. **When retiring an artifact, grep for the process that *produces* it, not just the readers that consume it.** The replacement text states the 2026-07-25 incident inline so the rule is not re-litigated from first principles.
- **`.github/agents/squad.agent.md` is a Squad *framework* file (v0.9.1), not project-local.** Editing it diverges this repo's copy from upstream, and its own §1013 rule says any change to it means the running session has stale coordinator instructions and the user must be told to restart. Flag both whenever touching it.
- **Said what I could not decide, in the index rather than only in the report.** README §8 lists six record groups left unjudged (the `*-required-fields-validation` set, the bug2-resubmission pair, the reference-directive evaluations, archetypes, name/description tables, favicon). An index that hides its own gaps is the artifact this whole exercise was replacing.
