### Global Search Phase 4a — entity long-text matching + real snippets (2026-08-01) — requested by Skyler Sidner, design in docs/search/{architecture,phases,open-questions}.md

Field order: `(EntityType, EntityId, Name, MatchedField, MatchedSubResourceName, MatchStrength, Weight, ExcerptSource, Snippet, MatchSpans)` — every positional-constructor call site (5 providers + `SearchServiceTests.cs`) needed updating.
- `SearchTokenizer` gained `CandidateField` (readonly record struct: `FieldName, Text, Weight, AllowSubstringTier, SubResourceName=null`) and `PickBestMatch(fields, tokens, rawQuery)` — evaluates every field via the existing `ComputeMatchStrength`, keeps the single highest `Score = MatchStrength * Weight`, ties broken by list order (first-listed wins, since the loop only replaces on strictly-greater score).
- New `Services/Search/SearchSnippetBuilder.cs`: `Build(fieldText, tokens, matchStrength) -> (Snippet, Spans)`. WindowRadius=70 const. Word-boundary trimming on **both** edges mirrors `ApiMappers.TruncateExcerpt`'s technique exactly (always cut back to the nearest space *within* the raw window, even if the raw cut already happened to land on a word boundary — same conservative "can't peek outside the window" behavior the existing trailing-edge trim has, so this isn't a new asymmetry, just applying the established technique symmetrically). Span-finding is a plain per-token `IndexOf` scan over the *final* snippet text (not gated by tier), then overlapping/adjacent (`span.Start <= lastEnd`) spans get merged.

- **`Program.cs` has no `UseRouting()` call.** `WebApplicationBuilder.ConfigureApplication` then inserts `UseRouting()` at the **front** of the pipeline (outer, ahead of all user middleware) and `UseEndpoints()` at the end. Consequences worth remembering repo-wide: `StaticFileMiddleware` and `DefaultFilesMiddleware` both start with `context.GetEndpoint() == null` and no-op when an endpoint has matched, and `MapFallbackToFile`'s `{*path:nonfile}` **matches `/`** (catch-alls match zero segments) — so with implicit routing, `UseDefaultFiles()` never fires and `/` is served by the fallback *endpoint*. - **`ForwardedHeadersOptions` defaults to loopback-only** (`KnownNetworks = { ::1/128 }`, `KnownProxies = { ::1 }`) and `ForwardedHeadersMiddleware` `break`s out of the entry loop at the first non-known hop — which discards `X-Forwarded-Proto` too, not just `X-Forwarded-For`. Bare `UseForwardedHeaders(...)` behind a container platform LB / nginx sidecar / CDN does **nothing**. Must pair with `KnownNetworks.Clear(); KnownProxies.Clear();` (which is exactly what `ASPNETCORE_FORWARDEDHEADERS_ENABLED=true` does internally, per the framework's own source comment).

Never bind an npm/ng build to `Build`: `MonsterOfTheWeek.Api.Tests` has a `ProjectReference` to the API, so `dotnet test` would trigger it.
