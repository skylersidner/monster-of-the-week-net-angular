### 2026-08-02: Theming Plan — Add `--color-surface-hover`; Defer `--color-accent-muted`
**By:** Yoshi (Architect)

**What:** Added `--color-surface-hover` to the Token Catalogue in `docs/theming/theming-plan.md` — role: "neutral hover-state fill for secondary/neutral surfaces (e.g. a Cancel button, a neutral list-item hover), distinct from the brand-colored `--color-accent-subtle`." Current light value it replaces: `gray-200` (the hover shade only — `gray-100` stays mapped to the existing `--color-surface-sunken` token, unchanged). Confirmed Category A (no utility-family word in the name — `hover` is a Tailwind variant prefix, not a color-consuming family — so it lives in the existing `@theme static` block and auto-generates `bg-surface-hover`/`hover:bg-surface-hover`, no hand-written `@utility` needed). Marked explicitly "dark value: Rosalina's call," since this token postdates `dark-theme-palette.md` and isn't in that document's value table yet, unlike every other Catalogue row.

Corrected Phase 2's text to state the confirm-delete modal's Cancel button hover (`hover:bg-accent-subtle`) is a known, flagged placeholder pending this token, not the adopted pattern — Luigi replaces it with `hover:bg-surface-hover` once Rosalina supplies the dark value. Updated Phase 3 (`minion-detail`), Phase 4 (`monsters-list`, `locations-list`, `bystanders-list`, `search-results`), and Phase 5 (`monster-detail`) to reference `bg-surface-hover`/`hover:bg-surface-hover` as the correct class for their identical `bg-gray-100`-shaped hover literal, instead of reinventing Luigi's workaround. Explicitly noted `--color-accent-muted` (a separate, smaller gap Luigi flagged — `custom-select`'s sub-label lost a lighter-accent shade distinction) is deliberately **not** added at this time, per Skyler — a one-line note so it isn't rediscovered as new.

**Why:** The gap was real and recurring (six sites across Phases 2-5), and the existing stopgap (`hover:bg-accent-subtle`) actively misrepresents a neutral gray hover as a brand-colored one. A single new token, scoped narrowly to the hover shade (leaving `--color-surface-sunken`'s existing job untouched), closes it for every later phase in one motion — the same reasoning this plan already uses everywhere else for adding a Catalogue row once a pattern is shown to recur rather than reinventing it phase by phase.

**Flagged, not fully resolved:** the token's canonical light value (`gray-200`) comes from the confirm-delete modal's base/hover pair. The five later-phase sites use a different shape — no separate base, just `hover:bg-gray-100` — so repointing them onto `bg-surface-hover` is a one-step visible darkening in light mode (`gray-100` → `gray-200`), not a strict pixel no-op like most of this plan's other repoints. Called out inline in Phases 3/4/5; treat as accepted unless Rosalina/Skyler want the two neutral-hover shades kept distinct instead.
