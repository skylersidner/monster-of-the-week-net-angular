### 2026-08-03: Mystery Badge Token — Kept Amber, Not the Earlier Speculative Teal
**By:** Rosalina (Designer)
**What:** Filled in the previously-reserved `--color-badge-mystery`/`--color-on-badge-mystery` rows in `docs/theming/theming-plan.md`'s Token Catalogue and `docs/theming/dark-theme-palette.md`'s Token Value Table. Values: light `amber-100`/`amber-700` (unchanged — matches the literal already shipping), dark `amber-950`/`amber-300` (same deep-950-bg/light-300-text construction as every other domain badge).
**Why:** The token had been treated as speculative ("reserved... if/when mysteries get a type badge"), and my own original palette doc floated `teal-100`/`teal-800` (light) / `teal-950`/`teal-300` (dark) on that assumption. That assumption was stale: `mysteries-list.html`, `mystery-detail.html`, `mystery-create-dossier.html`, and `search-results.ts`'s domain-badge map already render `mystery.adventureType.name` via a literal `bg-amber-100 text-amber-700` chip — and it already appears side-by-side with every other domain badge on the global search results page, which is exactly the scenario a hue clash would matter most. Given the badge already ships, my own hue-preservation philosophy for badges (don't let an already-shipped badge "swap identity" between themes) argues for keeping amber rather than replacing it with an unused speculative hue — switching would cost real visual-identity continuity for zero functional gain. Checked the amber-vs-orange (minion) adjacency directly at both badges' actual values in both themes and found them clearly distinct, not just theoretically distinct.
**Contrast:** `amber-300` on `amber-950` (dark) ≈ 10.4:1. `amber-700` on `amber-100` (light — the existing, already-shipped pairing, hand-verified for the first time here) ≈ 4.51:1 — passes AA for normal text but tightly.
**Follow-up for Luigi:** `search-results.ts`'s `DOMAIN_BADGE_CLASSES['Mystery']` still hardcodes the literal `bg-amber-100 text-amber-700` (with a doc comment calling it "reserved and unused," now stale) instead of `bg-badge-mystery text-on-badge-mystery` — worth re-pointing onto the token next time that file is touched, same as the other four domain badges already are.
