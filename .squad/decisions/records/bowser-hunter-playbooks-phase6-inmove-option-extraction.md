### Hunter Playbooks — Phase 6 in-move option extraction built, and two `custom-moves-ideation.md` claims corrected against the source (2026-08-30)
**By:** Bowser (Backend Developer / DevOps)
**What:** Built the two "Tooling prerequisites" in `docs/hunter-playbooks/custom-moves-ideation.md` Section 5 into `extract-moves.mjs` (an inline comma/semicolon option path, and delimiter-derived `Title` splitting as the default for in-move content), and while verifying them against the source PDF found that **two of the doc's own factual claims are wrong or incomplete** — both material to Phase 6 authoring, so recorded here rather than only in the pipeline log. (1) **Section 2.5(a) / Section 5 item 2 say there is no font-derived `Title` boundary anywhere in this content class — "not an exception, it's the rule for this entire content class". That is not universally true.** The Searcher's First Encounter (page 45, one of the fourteen in-scope moves, Required) has genuinely **bold** option names — "Cryptid Sighting" is `WarnockPro-Bold`, checked directly against the raw pdf.js item stream, not inferred from the extractor's own classification. The doc's claim was verified on exactly two cases (Crooked p11 inline, Host p31 bulleted) and generalised. Across the eight targets validated this pass the style tally is 81 regular / 7 bold, all 7 being First Encounter's — so the rule is a sound *default* and unsound as a *guarantee*. (2) **Section 5 says the bulleted path already works and only the inline path is missing. It does not work for in-move content**, on two independent counts: a **capital `B` FateCoreGlyphs glyph marks a Required move** and was not recognised as a bullet at all (so every Required move's whole body was silently absorbed into the preceding segment, or into `intro` when it came first — demonstrated against the pre-change extractor on Host p31, which put all of Defensive Adaptation into `intro` glyph-and-all and emitted its six options as six title-less top-level "moves"); and **in-move option bullets use the same `b` glyph as top-level move bullets**, separated only by x-indent (Host p31: 521.2 vs 503.2; same on Searcher p45, Visitor p55, Forged p23). Also recorded as a checked negative: the marker form does **not** distinguish a creation-time pick from an in-play menu — Spell-Slinger's Tools and Techniques (creation-time) and Could've Been Worse (in-play) both use `•` on the same page.

**Why:** Phase 6 authoring is about to start against these fourteen moves, and both errors would have cost real work. The font-signal claim was going to be recorded "as the standing expectation by default rather than re-flagging it per playbook" — which would have quietly downgraded the provenance of the one playbook where the source *does* corroborate the title. The tooling therefore **measures** it per option (`titleStyle`, `titleFontCorroborated`) rather than assuming it, while still deriving the boundary from the delimiter, which stays correct even where a font signal exists (an option is often one single text item, and a bold run alone cannot say where the title ends). The bulleted-path gaps would have been worse: the failure is silent and produces plausible-looking output, and seven of the fourteen in-scope moves are Required. Two further consequences worth acting on beyond this pass: **(a)** `titleProvenance: "delimiter:paren"` always needs a human decision and must not be auto-accepted — the counterexample pair is in the source, not hypothetical (Gumshoe's "Criminals (organised)" where the parenthetical is part of the *name*, vs. Crooked's "Protective amulet (1-armour magic recharge)" where it is the description); **(b)** the census may not be complete — the new inline path fired on **The Monstrous's already-authored Phase 5 bespoke option "Pure Drive"** (p37), which contains its own creation-time inline pick-1-of-11 ("Pick from: hunger, hate, anger, fear, jealousy, greed, joy, pride, envy, lust, or cruelty"). That is a pick nested inside a *bespoke option*, which Section 2.1 does not scope (it covers picks inside Moves) and which is not recorded as a structured pick anywhere. Flagged for Yoshi/Skyler, not acted on. All new output is behind an additive `--options` flag so every one of the 19 prior build scripts' outputs is byte-identical (verified by md5 against the committed git blobs), and when option structure is detected without the flag the script now says so on **stderr** — the original defect the census named was the silence, not the absence, and stdout stays untouched so no existing caller can change. Full detail in `docs/hunter-playbooks/pdf-extraction-pipeline.md`'s "Nineteenth pass" section; reviewable output in `tools/pdf-extract/custom-moves-tooling-review.html`/`.json`.
