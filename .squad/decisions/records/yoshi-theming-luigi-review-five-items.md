### 2026-08-02: Theming Plan — Luigi's Five Pre-Phase-1 Review Points, Resolved Per Skyler
**By:** Yoshi (Architect)
**What:** Edited `docs/theming/theming-plan.md` in place to address five points Luigi raised reviewing the plan (plus Rosalina's palette doc) before starting Phase 1 implementation:
1. **Token naming vs. Tailwind-generated utility classes — held open, not decided.** Confirmed against Tailwind v4's own `@theme` docs: a `--color-*` token's utility name is the literal remainder after `--color-`, reused verbatim under every color-consuming prefix (`bg-`, `text-`, `border-`, `ring-`, etc.) — no parsing/stripping of a trailing word. So `--color-toast-success-bg` compiles to `bg-toast-success-bg`, not `bg-toast-success` as the plan's own Phase 1 prose implied — a real functional risk (silently unstyled element, no build error), not just ugly naming, and it affects every `-bg`/`-text`-suffixed token in the catalogue (toast x2, all 6 badge rows, weapon-chip), not just toast/badges. Separately, *every* token (not just these) is technically available under every color-prefix utility (`bg-text-primary`, etc.) — that part is universal but harmless (Tailwind's generator is on-demand, no dead-CSS bloat), a soft semantic-misuse risk at most. Added a "Pending decision — awaiting Skyler" subsection right after the Token Catalogue recommending the `on-*` convention already used for `--color-on-accent`/`--color-on-danger` (e.g. `--color-toast-success` + `--color-on-toast-success`) — explicitly not applied to the catalogue yet.
2. **Decision D's `resolvedTheme` was invalid Angular** — fixed factually: a `computed()` can't own a `matchMedia` listener (must stay pure). Corrected to `toSignal(fromEvent(matchMedia, 'change'))` feeding a pure `computed()`. Also verified (cited `bootstrapApplication`, no hydration, `<html>` predates `app-root`) that the inline `<head>` script in Decision E is sound and survives Angular's bootstrap untouched. Per Skyler, decoupled the zero-flash guarantee from the core mechanism: Phase 0 still ships a fully working `ThemeService` (possible flash accepted), the inline script + "zero flash" goal move to a new, isolated Phase 8 after Phase 7. Risk Register FOUC rows updated to reflect the deferral.
3. **Settings picker widget** — clarified Luigi's actual point (no *existing* UI shape for a 3-way Light/Dark/System choice, not "a dropdown can't do it") and updated Decision I to explicitly name `CustomSelectComponent` (3 options) as the widget, replacing unspecified/implied-radio language.
4. **Stale "confirm with Rosalina" bullets in Phase 1** updated to state her actual resolutions as decided: Soon badge stays plain `bg-white/20`, no token; both modal scrims stay a fixed `bg-slate-950/55` literal in both themes, no token. Folded in her related spinner `currentColor` fix from the same section while there.
5. **Test-disabling sweep added to Phase 0 scope.** Grep-verified (not guessed) across every `*.spec.ts`: only one real hit app-wide — `search-results.spec.ts` asserts `bg-red-100`/`bg-green-100` literal badge classes. **`page-layout.spec.ts` was a false lead** — its `.sidebar-mobile`/`.api-modal` selectors are structural class names unrelated to color and don't need disabling; worth remembering not to trust a relayed "Luigi found X" claim without re-grepping. Also surfaced a real phasing gap: `search-results.html` (global search feature, shipped after this plan was drafted) independently renders the same monster/location badge tokens but was missing from every phase's Files-changed list — folded into Phase 4 (same Type Badge Pattern), which also becomes the one phase responsible for re-enabling the disabled assertions.
