### 2026-09-20: Mystery Entity Linking Phase 4 — the baseline is the one fact, and `idsToRemove` had to yield to it
**By:** Luigi (Frontend Developer)

**What:** Three implementation decisions that are not restatements of the design, recorded because each closes a gap the docs left to implementation and each would be easy to undo by accident.

**1. `membershipPersisted(collection, id)` is the single predicate, on the store.** Decision 16 and UX §7.1 both require the removal variant to key on the phase baseline rather than on `id`, and §14.2 asks that it be *the same predicate the submit diff uses* rather than a second implementation. It is one method over `existingLocationIds` / `existingBystanderIds`, called by the phase component for the variant and by `removeLocationDraft` / `removeBystanderDraft` to decide whether a disposition is recorded at all. There is no second copy of the question and no way for the modal and the diff to disagree about what removal will do.

**2. `idsToRemove()` now excludes ids that `pendingRemovals` owns — and this was a live defect, not tidying.** §7.3 says `pendingRemovals` is authoritative and `idsToRemove()` becomes a consistency check, but the shipped `idsToRemove` is a blind baseline diff. Left alone, a confirmed **Delete** produced *two* calls for one removal in the same `forkJoin`: the drain's `DELETE /api/locations/{id}` and the diff's `DELETE /api/mysteries/{id}/locations/{id}`, racing — and the unlink can 404 against the row the delete just destroyed, failing the whole phase with its generic error. §7.3's rule 2 would not have saved it, because rule 2 is scoped to the drain path and this call is not on it. The exclusion is four lines and a `collection` parameter that the minion caller leaves unset.

**3. §7.6 taken (Peach's G4, explicitly Luigi's call).** A successfully drained `delete` drops that id from the cached attach options, in the same bookkeeping step that already updates the baseline signal. Three lines, no new code path, and it closes the case where a `Back` re-offers an entity deleted earlier in the session and the membership `PUT` then 404s. **The 404-as-success rule was deliberately *not* extended to cover it** — a 404 on detach means the post-condition the user asked for already holds; a 404 on link means the thing being linked does not exist, which is the opposite, and mapping it to success would report a membership that was never created. That is the same false-success the Phase 2 duplicate-key gate rejected, and there is a negative control keeping it that way.

**Why / judgment calls:**

- **The duplicate-removal defect is the kind that passes review.** Both calls are individually correct; only their composition is wrong, and the symptom is an intermittent phase failure that looks like a network problem. It was found by writing D7 as "delete is issued **and** unlink is not" rather than just "delete is issued" — the negative assertion is the one that caught it.
- **One redundant guard deleted rather than annotated.** I first mirrored the minion phase's `validateCurrentStep` branch for phases 2 and 3 alongside the `commitComposerIfValid` call in `next()`. A negative control proved the pair unobservable for a single-step phase: both set the same message and both refuse. Removed, with a comment explaining why the asymmetry with phase 1 is deliberate, rather than leaving a branch no test can reach.
- **The wizard's "other mysteries" copy lives beside the list-page copy** in `shared/mystery-usage.ts`, not in a new file. The whole hazard in that pair is one word — "used by 2 mysteries" on a flat catalogue, "also used by 2 *other* mysteries" in the wizard — and the two functions being adjacent, with the reason in the header, is what makes the difference visible rather than rediscoverable.

**Verification:** `npx ng build --configuration production` clean, with the two pre-existing budget warnings. `npm test`: 83 files / 1007 tests, from a 951 baseline. Backend untouched and still 533. 24 negative controls applied and reverted, all caught; one MISSED and resolved by deleting the redundant code.
