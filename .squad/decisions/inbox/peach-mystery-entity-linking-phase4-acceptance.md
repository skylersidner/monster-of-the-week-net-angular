### 2026-09-20: Mystery Entity Linking — Phase 4 acceptance criteria are a third companion doc, not a section of the architecture

**By:** Peach (Product Owner / Business Analyst)

**What:** The Phase 0 assignment recorded at `mystery-entity-linking.md` §9 ("acceptance criteria for 'connect an existing object to a mystery' on both surfaces, and for the Detach/Delete removal contract in §7.1") is delivered as **`docs/updates/mystery-entity-linking-acceptance.md`**, scoped to what Phase 4 actually ships. The ownership rule already agreed between Yoshi's and Rosalina's docs is extended to three: **what the software must do to be accepted is mine; how it does it is his; how it looks and reads is hers.** Each cites the others and none restates them.

**Why a separate file rather than a `§13` in the architecture doc:** that document's own front matter scopes it to "architecture, API, data flow, phasing and agent ownership only," and its §12 already establishes a two-document split with an explicit ownership rule. A third companion matches the convention; a thirteenth section would have been the first thing in the file that isn't architecture. It also means Toad and Skyler can read the criteria without the architecture, which is the stated point of the deliverable.

**Scoped down, deliberately.** The assignment says "both surfaces," but the edit-form surface shipped in Phase 2 and the modal's input contract shipped in Phase 3, both with tests. Restating them as Phase 4 criteria would have produced a document where the shipped and the unshipped are indistinguishable. §1 carries a three-row table of what is already covered, and the criteria describe only the remaining gap.

**One criterion worth surfacing out of the document, because it is the easiest test to write wrong.** AC-A6: an attached entity that was not edited must have **identical field values** after the phase submit — assert the values, not the absence of a `PUT`. A no-op `PUT` of identical values is *expected* in Phase 4; the derived dirty check is Phase 5 and only for monsters (architecture §5.4). "No `PUT` is issued" would assert a requirement this phase does not have and would fail a correct implementation.

**Three gaps found, each routed rather than decided:**

1. **G1 — an edit-mode tracker jump silently discards a confirmed removal.** `jumpToPhase` (`mystery-create.store.ts:900`) does not submit, and `isPhaseAccessible` (`:909`) returns `true` for every phase in edit mode. So: trash a location, confirm **Delete**, click the Bystanders bubble, press Finish — phase 2 never submits and nothing is applied. The mechanism is pre-existing (today's unlink is lost the same way); what Phase 4 changes is that the discarded action is now confirmed and destructive. `Back → Next` is safe; the tracker jump is the only hole. **Routed to Yoshi** (submit semantics) with Rosalina on copy if the answer is "accept it."
2. **G2 — the deferred-execution footnote is false on the last phase.** Variants B and C say "the change takes effect when you continue to the next step"; Bystanders is `lastPhaseIndex` and its button says **Finish** (`mystery-create.html:34`). Needs a last-phase variant that still avoids "this cannot be undone" per UX §7.3. **Routed to Rosalina**, who is in that file today.
3. **G3 — "attached in this session, not yet submitted" is not in UX §7.1's variant table.** The table keys on `id === null` vs `id !== null`, and an attached entity has an `id` immediately. Attach by mistake, trash it a second later, and the modal offers Detach (a no-op against a membership that was never created — the absent-membership `DELETE` that 404s) and **Delete**, which destroys a catalogue entity the user only meant to un-attach. The distinguishing state needs no new store state: the `id` is simply not in the phase's baseline (`existingLocationIds()`). **My product position, offered as input:** that case should be a plain **Remove**, with catalogue deletion staying on `/locations` where Phase 3 just gave it disclosure. **Routed to Rosalina** (variant) and **Yoshi** (whether the diff keys on the baseline rather than on `id`).

**Not done, and it needs one line from someone with Edit:** a pointer from `mystery-entity-linking.md` §9's Phase 0 block to the new file. The Edit tool was disabled for this session and rewriting a 582-line document owned by another agent to add a cross-reference was not a trade worth making.
