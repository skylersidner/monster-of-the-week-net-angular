### 2026-08-03: Theming Plan — Add `--color-on-success`
**By:** Yoshi (Architect)

**What:** Added `--color-on-success` to the Token Catalogue in `docs/theming/theming-plan.md`, immediately after `--color-success` — role: "Text/icon color placed on a success-filled surface (e.g. the wizard's complete-phase bubble)," current light value `white`. Confirmed Category A (no utility-family word in the name — stays in the existing `@theme static` block, auto-generates `text-on-success`/etc., no hand-written `@utility` needed). Added the matching row to `docs/theming/dark-theme-palette.md`'s Token Value Table: light `white`, dark `slate-900` (`#0f172a`) — copied directly from `--color-on-accent`'s existing row, not re-derived. Added a short resolution note in Phase 6's section of `theming-plan.md` stating the gap is closed and that Luigi's placeholder swap (`text-on-accent` → `text-on-success` in `mystery-create.scss`) is still pending, not done as part of this change.

**Why:** Luigi's Phase 6 review (`.squad/decisions/inbox/luigi-theming-phase6-mystery-wizard.md`, item 1) found `--color-success` was the only fill role in the Catalogue with no `on-*` partner, and shipped an explicitly-flagged placeholder (`text-on-accent`) rather than invent a value unilaterally. The placeholder was numerically correct in both themes — `--color-on-accent` (light `white`, dark `slate-900`) already holds exactly the values an `on-success` token would need under Rosalina's own lighten-and-flip construction — but semantically wrong: a success surface reading an accent token. Skyler's call was to formalize this now with those specific values rather than leave it to diverge later, matching the precedent already set for every other fill token in the Catalogue (`on-accent`, `on-danger`, `on-badge-*`, `on-toast-*`, `on-weapon-chip`).

**Scope note:** this was a documentation-only change to the two theming docs. The actual `mystery-create.scss` edit (swapping the placeholder reference) is explicitly left for Luigi.
