### 2026-08-02: Theming Phase 0 — Two Judgment Calls Made During Implementation
**By:** Luigi (Frontend Developer)
**What:**
1. **`--color-badge-mystery`/`--color-on-badge-mystery` NOT added to `styles.css`'s `@theme`/`.dark` blocks yet.** The Token Catalogue lists this pair as reserved with "n/a today" for its current light value, and the plan explicitly says Rosalina's speculative `teal-*` proposal for it is not adopted. Phase 0's own constraint is that every token's light value must equal a *current* literal color already in use — there is no current color for a badge that doesn't exist, so declaring the pair now would mean inventing a value the plan explicitly declined to commit to. Left both tokens undeclared; add them (with a real, decided value) whenever a mystery type badge actually ships.
2. **`search-results.spec.ts`'s test-disabling sweep: split into two tests instead of `it.skip`-ing the original one.** The original test (`'renders the correct domain badge/icon/link for each entityType'`) asserted the two literal-color lines (`bg-red-100`/`bg-green-100`) alongside several unrelated, non-color assertions (icon `domain` values, link `href`s). Vitest's `it.skip` disables an entire test body, not individual `expect()` lines, and the plan's own phrasing ("disabled … on the containing test") doesn't resolve that tension. Rather than skip the whole test (losing icon/link coverage until Phase 4) or leave the color assertions in place (contradicting the plan), I extracted the two color assertions into a new, dedicated `it.skip(...)` test with the Phase-4 re-enable comment, and kept the original test's remaining (non-color) assertions running normally.
**Why:** Both are genuine ambiguities in `docs/theming/theming-plan.md` as written, not places I overrode a stated decision — flagging so Yoshi/Skyler can confirm or redirect before Phase 4/7 lands.
