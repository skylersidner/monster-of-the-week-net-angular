### 2026-08-02: Theming Phase 7 — Sweep Scope Widened to Include Dead/Unused Legacy CSS
**By:** Yoshi (Architect)

**What:** Added an explicit instruction to Phase 7's "Sweep for stragglers" item in `docs/theming/theming-plan.md`: whoever executes Phase 7 must actively examine every component `.scss` file — every one touched across Phases 1-6, and any that weren't touched at all, in case it carries its own leftover legacy rules — for dead, unused legacy selectors left over from any point in this app's styling history. This is in addition to, not a replacement for, Phase 7's existing literal-color-class and `@reference` checks.

**Why:** Luigi's Phase 4 pass (`.squad/decisions/inbox/luigi-theming-phase4-list-pages.md`) found ~90 lines of pre-migration dead CSS in `monsters-list.scss`, including a second, duplicate `.action-btn:hover:not(:disabled)` rule — same specificity, later in source order — that was silently winning the cascade over the newly token-repointed rule. Left in place, it would have permanently pinned that button's hover color to its old literal value in both themes the moment real dark values landed in Phase 7, invisible until that exact point. This is a distinct failure shape from anything Phase 7 already checks for: dead CSS still compiles and emits like any live rule, it simply never matches anything in the current templates, so it's invisible to both "does this class emit a rule" tooling and to a grep that only looks for classes that *are* referenced anywhere. Skyler asked this be generalized rather than treated as a one-off fix specific to `monsters-list.scss`, since any other component `.scss` file could be carrying the same kind of latent, cascade-order landmine.

**Scope discipline:** this is one addition to Phase 7's existing scope, not a new phase and not a rewrite — Phase 7's Goal/Risk/Files/Inspection Points sections are otherwise unchanged.
