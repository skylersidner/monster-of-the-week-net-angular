## What

Wrote `docs/hunter-playbooks/{README,architecture,phases,open-questions}.md` from scratch, replacing the deleted 2026-08-24 doc, against a materially narrower and re-sequenced brief from Skyler (9 phases, only 3 of 28 playbooks read this pass: The Chosen, The Crooked, The Divine). Key calls:

- **Read Chosen/Crooked/Divine directly from a fresh `pdftotext -layout` extraction** rather than reusing prior content conclusions. Caught two real column-layout artifacts in the process: (1) the apparent per-stat move pairing on every playbook's front sheet is spurious — it's two unrelated static columns (blank rating boxes; the fixed, universal 8-basic-move list) merged onto matching line numbers by `-layout`, not real data; (2) an early read pulled in trailing content from the previous playbook in the PDF (page-bleed), caught by cross-checking wording against the other two playbooks before trusting it.
- **Data model** (`architecture.md` Section 3): extends the existing `MonsterArchetype`/`WeaponTag`+bridge-table precedent. `Playbook` + `PlaybookStatArrayOption`/`PlaybookMove`/`PlaybookGearCategory`→`PlaybookGearOption`/`PlaybookLookCategory`→`PlaybookLookOption`/`PlaybookImprovement` (flat, `IsAdvanced`-flagged, no semantic sub-typing). The Improvements/Advanced Improvements finding is the strongest result of this pass: predicted by Skyler to be "some standard, some bespoke," and that's true at the option-text level, but the *section itself* is 100% structurally uniform across all three (10 Improvements, 7–8 Advanced, several items word-for-word identical) — needs zero special-casing beyond one flat table.
- **Gear turned out more varied than Skyler's own "named presets" guess** — Chosen's "special weapon" is a genuine build-your-own (pick a form + 3 modifiers + a material), not a flat list, but it still decomposes into the same `PlaybookGearCategory`(nullable `PickCount`, `IsOptional`)→`PlaybookGearOption` shape with zero new concepts needed.
- **Cloud-deployment/seeding recommendation reverses the prior pass's call, for a stated reason**: Skyler's own Phase 3 (Admin UI create/update) and Phase 4 (import via that UI) mean Playbooks are ordinary admin-authored domain rows created through the running app against whichever DB it's pointed at — not `MotwDbInitializer` seed data, and no JSON seed file needed at all. This makes the "must work in production too" constraint a non-issue rather than a deploy-pipeline design problem, since the Admin UI already *is* the production data-entry path for this kind of content.
- **Phase 9 (Hunter create/edit): recommended a single-page reactive form over a wizard**, with the deciding argument being that the Mystery wizard's complexity exists specifically to sequence ordered child-entity creation (Monster needs an Id before Attacks attach) — a problem Hunter doesn't have, since everything is data about the Hunter itself, submittable in one request. The one real complication (nothing renders until a Playbook is picked) is solved with a reactively-gated single page, following two patterns already in this codebase (`data-admin.ts`'s table selector, `monster-create.ts`'s `isSpecial`-conditional validator), not a second navigation step.
- **Flagged, not solved: Crooked alone has three distinct bespoke concepts** (Background/Heat/Underworld), not one — meaning the Phase 2 placeholder (`Playbook.UniqueMechanicText`, single free-text field) is likely insufficient once Phase 5 is actually designed. Stated as a hypothesis for Phase 5 to validate against more playbooks, explicitly not designed this pass per the brief.
