### Hunter Playbooks — PDF extraction pipeline confirmed immune to The Forged's column-2/column-3 stream-order defect (2026-08-27)
**By:** Bowser (Backend Developer / DevOps)
**What:** Skyler found that The Forged's PDF pages have a genuine text-stream/reading-order defect — the 3-column layout renders correctly, but the underlying stream order has columns 2 and 3 swapped (Col1→Col3→Col2 instead of left-to-right), which caused a real misclassification on Yoshi's structural-analysis side. Assessed directly (not assumed) whether `tools/pdf-extract`'s extraction pipeline is exposed. **Confirmed immune, by construction, verified two independent ways**: (1) `extract-runs.mjs`/`extract-moves.mjs` select column content purely by each text item's own embedded x/y coordinates (`item.transform[4]`/`[5]` vs. `--minX`/`--maxX`/`--minY`/`--maxY`), never by stream/array order — there is no code path that reasons about "which block comes first," so a block-order swap has nothing to act on; (2) confirmed the swap operates at the whole-column-block level (one contiguous run of items relocated ahead of another), not as an item-by-item scramble — verified page 23's middle-column block (items 253–415) has strictly decreasing y with zero interleaving, so within-column sentence reconstruction (which does rely on the surviving items' relative order) is also unaffected. Cross-checked against the actual already-shipped `forged-review.json` output, produced before this defect was reported: reads as coherent, correctly-ordered English with zero cross-contamination from the adjacent third-column content.
**Why:** This matters beyond Forged — it means all previously-extracted formatting content across every playbook this pipeline has processed (11 passes: Crooked, Covenant ×2, Divine, Chosen, Action Scientist, Changeling, Curse-eater, Envoy, Expert, Forged) remains trustworthy with respect to this specific class of defect, with no re-extraction needed, even though Yoshi's separate page-level structural reads (which appear to have followed logical/stream order, e.g. drag-select) may need re-checking on affected playbooks. This is a property of the pipeline's x/y-coordinate-based technique, not a one-off fact about Forged, and generalizes to any future page found to have the same defect — it's exactly why this pipeline was built on `pdf.js`'s per-item embedded coordinates rather than any stream-order-following method in the first place. Full assessment, including the raw-data verification steps, is documented in `docs/hunter-playbooks/pdf-extraction-pipeline.md`'s "Pipeline-integrity check" section. One caveat stated explicitly there, not glossed over: this confirms immunity to *this specific, now-verified* block-level swap behavior — it doesn't blanket-guarantee immunity to every conceivable future PDF-generation defect, so each new page still gets the same "does the output read as coherent English" sanity check already standard in this pipeline's review discipline.
